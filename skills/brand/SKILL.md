# brand — 브랜드 색·테마 만들기

Rules.md·Design.md를 먼저 읽는다. 테마가 바꿀 수 있는 슬롯과 못 바꾸는 슬롯은 `vault/themes/README.md`가 정한다(상태색·시장 방향색·발산 램프는 고정).
사용자는 디자인 지식이 없다. 질문은 **고를 수 있는 보기**로 묻고, 결정은 **실제 쓰일 화면을 보고** 하게 한다. 색 견본 칩만 보여 주고 고르게 하지 않는다.

## 1. 브리프 — 두 번에 나눠 묻는다 (AskUserQuestion, 회당 최대 4문항)
모르는 건 "모름"을 허용하고 기본값으로 진행한다.

**1회차: 색·느낌은 묻지 않는다.** 처음부터 색을 물으면 흔한 답(파랑=신뢰)으로 굳는다(impeccable `init`).
1. 누가, 언제 오나: 수험생 / 대학생 / 직장인 / 섞임 — 주 이용 시간대(낮·밤·심야)
2. 이 매장만 가진 것: 위치(역 앞·주택가·학원가), 시설(1인실·스터디룸·카페존), 운영 방식(무인·상주), 사장님 이야기. 가격 위치(동네 최저가 / 중간 / 프리미엄)도 여기서
3. 바꿀 수 없는 것: 간판·로고·인테리어 색(사진 받기), 프랜차이즈 규정 — 프랜차이즈면 본사 CI가 우선이므로 **이 스킬은 부가 화면 테마만** 잡는다
4. 쓰일 곳 우선순위: 간판·외벽 / 실내 사인 / 키오스크·좌석 배정 화면 / 앱·웹·네이버 플레이스 / 인스타 / 인쇄물(가격표·전단)

**2회차 (경쟁 조사 뒤):**
5. 어떤 느낌으로 기억되고 싶나(형용사 3개): 차분한 · 집중되는 · 따뜻한 · 고급스러운 · 밝고 경쾌한 · 미니멀한 · 자연 친화 · 단단한
6. 피하고 싶은 느낌: 학원 같음 · 병원 같음 · 카페 같음(놀러 오는 곳) · 유치함 · 차가움

브리프를 받으면 **"이 매장만 가진 것" 3개**를 한 줄씩 적어 사용자에게 확인받는다. 후보의 가설은 이 3개에서 나온다.

## 2. 경쟁 조사 (browser-router 스킬 경로로)
- 반경 1km 안 경쟁 매장 5~10곳의 대표색을 모은다: 네이버 지도 플레이스 사진·간판, 인스타 피드, 프랜차이즈 공식 사이트.
- 결과를 표로: 매장명 / 프랜차이즈 여부 / 대표색(hex 근사) / 느낌 한 단어.
- 색상환(OKLCH hue 0~360) 위에 경쟁 매장 색을 찍어 **비어 있는 각도**를 찾는다. 같은 길에 같은 색 간판이 두 개면 둘 다 기억에 남지 않는다.
- 참고: 업계 흔한 색을 알려 주되 그걸 피해야 한다고 단정하지 않는다. 사용자가 고른다.

## 3. 후보 5개 — 개념이 다르게
- 축: 색상각(경쟁이 비운 각도 우선) × 채도(차분 ↔ 선명) × 바탕 온도(따뜻한 무채색 ↔ 차가운 무채색).
- 각 후보: 이름 + 한 줄 가설 + seed hex. 가설에는 "이 매장만 가진 것" 중 하나가 들어간다("깊은 숲 초록: 공원 옆 2층이라 창밖 나무와 이어지고, 근처 경쟁 4곳이 모두 파랑·검정이라 구분된다").
- **이름 바꾸기 시험:** 가설의 매장 이름을 근처 경쟁 매장 이름으로 바꿔도 말이 되면 그 후보는 버린다. 아무 매장에나 붙는 색은 기억되지 않는다.
- 로고가 있고 브랜드색이 따로 없으면, 로고에서 가장 넓게 쓰인 색을 **후보 1번**으로 반드시 넣는다(앱인토스 가이드).
- 만들기 전에 "비슷한 요청에 내가 기본으로 낼 색"을 한 줄 적고, 후보가 그것과 같으면 바꾼다(스터디카페라면 흔한 기본값: 남색·검정+노랑·민트).
- seed마다 `scripts/tokens/ramp.py <seed>`로 12단계 사다리와 슬롯 제안을 만든다. `--css <이름>`으로 theme.css 초안.
- 다크 사다리는 라이트를 뒤집지 않고 따로 정한다(ramp.py가 그렇게 만든다). 다크 바탕은 순흑 대신 브랜드 hue를 아주 약하게 섞는다.
- 바탕 온도를 바꾸는 후보는 `ramp.py <seed> --neutral 0.008`(채도 0.005~0.012)로 `--bg`·`--surface*`·`--border*`·`--text*`까지 같은 각도의 무채색으로 만든다. 붉은 seed라 바탕이 분홍으로 뜨면 `--neutral-hue 75`(따뜻한 회색)로 각도를 따로 준다.
- 글꼴도 후보에 포함할 수 있다(제목용 `--font-display`만). 상업 이용 무료(OFL 등)인지 확인하고 출처 URL을 적는다. 본문은 Pretendard 유지.

## 4. 실제 화면에 입혀 비교 (explore 방식)
`scripts/new.sh <브랜드>-brand-explore`로 폴더를 만들고, 후보마다 같은 목업 세트를 그린다. 스터디카페 기본 세트:
1. 간판 시안(가로 띠, 낮/밤 — 밤은 어두운 배경에 조명 글자)
2. 키오스크 좌석 선택 화면(좌석 배치도: 빈 좌석 / 사용 중 / 내 좌석 / 고장, 남은 시간)
3. 이용권 가격표(시간권·기간권·사물함)
4. 네이버 플레이스·인스타 공지 카드(1080×1080 비율)
5. 이용 현황 대시보드(사장님용: 오늘 이용자 수, 좌석 점유율, 시간대별 막대 — 하네스 차트 규칙 그대로)
- 다른 업종이면 그 업종의 "실제 쓰일 곳" 5개로 바꾼다.
- 한 페이지에 후보 = 열, 목업 = 행으로 놓아 같은 목업끼리 가로 비교가 되게 한다. 데이터는 실제 같은 한국어(좌석 번호, 가격 "4시간 6,000원").

## 5. 검증 (통과 못 하면 후보에서 빼거나 고친다)
- `scripts/tokens/check_theme.py <테마>` — 라이트·다크 대비(글자 4.5:1, `--on-accent`).
- `scripts/tokens/ramp.py <seed>` 출력의 **단계 계약** 4줄이 모두 통과인지(11단계 글자 on 1단계 4.5:1, 12 on 2 7:1, on-accent on 9 4.5:1, 입력창 테두리로 쓸 단계 on 1단계 3:1). KRDS "단계 차 = 대비" 원리를 12단계에 옮긴 것.
- **상태색과 겹침:** 브랜드 hue가 `--positive`(초록)·`--negative`(빨강)·`--warning`(황토)과 30° 안이면 경고한다. 빨강 계열 브랜드는 `--up`(시장 상승)과 겹치므로 시세·매출 증감 화면에서는 UI 강조에만 쓰고 데이터에는 쓰지 않는다.
- **색 면적:** 화면·앱은 바탕·중립 60 / 보조 30 / 강조 10(KRDS), 강조색 사용처 3곳 이하(Design.md §1). 간판·홍보물은 강조 면적 10% 이하로 시작해 실물을 보고 늘린다.
- 범주 1번(`--series-1`)을 브랜드색 계열로 바꿀 거면 dataviz 검증기 재실행(방법은 `vault/themes/README.md`). 통과 못 하면 차트 1번은 기존 틸 그대로 두고 브랜드색은 UI에만 쓴다 — 그래도 된다.
- 색각이상: 좌석 상태처럼 색으로 구분하는 곳은 **색 + 모양/글자**를 같이 쓴다(빈 좌석 테두리만, 사용 중 채움+시계 아이콘). 색만으로 구분하는 설계는 후보와 무관하게 실패.
- `scripts/verify.sh <폴더>` + 스크린샷 직접 보기.
- 실물 주의(보고에 적는다): 간판·인쇄물의 실제 색은 화면과 다르다. 확정 전 인쇄소·간판 업체에 **실물 샘플**(팬톤/CMYK 근사값 지정)을 받아 매장 조명 아래에서 본다. hex는 화면 기준값일 뿐이다.

## 6. 수렴 → 고정
- 사용자에게: 비교 페이지 링크 + 후보 5개(이름·가설·대비 수치) + 내 추천 1개와 이유. 섞기("A 색에 B 바탕")도 받는다.
- 결정되면:
  1. `vault/themes/<이름>/theme.css` — 최종 슬롯 값
  2. `vault/themes/<이름>/brand.md` — 브랜드 가이드 한 장: 대표색(hex·용도·쓰면 안 되는 곳), 보조색, 바탕, 글꼴, 문구 톤(Design.md §11을 이 브랜드에 맞게 — 예: 공지는 해요체, 규칙 안내는 짧은 명사형), 간판·인쇄용 근사값(확인 필요 표시), 결정 근거(경쟁 조사 표, 버린 후보와 이유)
  3. `scripts/tokens/build.py --theme <이름>` — DTCG·Tailwind·DESIGN.md 사본 생성(외부 디자인 도구·간판 업체 전달용)
  4. 버린 후보 중 이유가 분명한 것은 `vault/rejected/`로
- 하네스 기본 테마(틸)는 바꾸지 않는다. 브랜드 테마는 그 브랜드 작업에서만 tokens.css **다음에** theme.css를 로드해 쓴다.
