# explore — 넓게 탐색 → 나란히 비교 → 수렴

원문 3단계("AI로 범위 탐색")의 절차. Rules.md·Design.md를 먼저 읽는다.

## 1. 재료 확인 (빈 페이지 금지)
- 대상: 어떤 화면/컴포넌트인가? `outputs/`의 기존 프로토타입, `vault/components.html`, 사용자가 준 URL·스크린샷 중 무엇이 출발점인지 정한다.
- 출발점이 없으면 묻는다. 추측으로 빈 화면에서 시작하지 않는다.

## 2. 축 정하기
변형은 **개념이 달라야** 한다. 색만 바꾼 8개는 탐색이 아니다. 먼저 축을 2~3개 적는다. 예:
- 정보 구조: 목록형 / 카드형 / 표형 / 타임라인형
- 밀도: 한눈 요약 / 전문가용 촘촘함
- 주 행동의 위치: 상단 고정 / 인라인 / 하단 시트
- 톤: 차분함 / 단호함 / 편집 디자인풍

## 3. 생성
- 기본 6개(사용자가 수를 말하면 그 수). 각 변형에 **이름 + 한 줄 가설**("표형: 비교가 주 작업이면 가장 빠르다")을 붙인다.
- 넓은 시각 탐색을 원하면 랜덤 문자열 시드를 만들어(예: `C8IPOW62`) 각 변형의 색·타입·간격 방향을 그 시드에서 끌어낸다. 이때도 토큰 체계(변수 이름)는 지키고, Design.md를 벗어나는 값은 그 페이지 안에 **변형 전용 토큰**으로만 선언한다.
- 변형이 많으면 서브에이전트로 병렬 생성해도 된다.
- 결과물: `scripts/new.sh <slug>-explore`로 폴더를 만들고, 한 페이지에 변형을 격자로 나란히(데스크톱 2~3열, 모바일 1열) 놓는다. 각 칸 위에 번호·이름·가설.

## 4. 검증
- `scripts/check.sh <폴더>` — 변형 전용 토큰 외 드리프트 0
- `scripts/shot.sh <폴더>/index.html <스크래치>` — 스크린샷을 **직접 보고** 서로 너무 비슷한 변형은 교체한다.

## 5. 수렴
- 사용자에게: 링크/경로 + 변형 목록(번호·이름·가설 한 줄씩) + 내 추천 1개와 이유.
- 사용자가 고르거나 지우거나 섞으라고 하면 `-v2` 폴더에서 한 방향으로 다듬는다. 원래 탐색 폴더는 지우지 않는다.
- 사용자가 버린 변형 중 이유가 분명한 것은 세션 마무리 때 `vault/rejected/`로 간다.
