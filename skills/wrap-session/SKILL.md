# wrap-session — 학습 누적

원문 5단계("세션 끝에 교정 기반으로 규칙 업데이트"). 하네스는 이 단계 때문에 세션마다 좋아진다.

## 1. 수집 (이 대화에서만, 추측 금지)
대화를 되짚어 세 목록을 만든다. 각 항목에 **사용자의 실제 말**을 짧게 인용한다.
- **교정**: 사용자가 바꾸라고 한 것 ("이건 너무 크다", "파란색 말고")
- **잘 된 것**: 사용자가 그대로 두거나 칭찬한 패턴
- **실수**: 내가 규칙을 어겼거나 다시 해야 했던 것

## 2. 분류·반영
| 종류 | 어디로 |
|---|---|
| 시각 값·컴포넌트 규격 | `Design.md` 해당 섹션 + `vault/tokens.css` (둘은 항상 같이) |
| 작업 방식·도구·금지 | `Rules.md` 해당 섹션 |
| 처음 나온 교정 | `Rules.md` 교정 로그에 한 줄 (횟수 1) |
| 두 번째 나온 교정 | 로그 횟수 올리고 **규칙으로 승격** |
| 잘 된 컴포넌트 | `vault/components.html`에 추가 (토큰만 쓰는지 `scripts/check.sh`로 확인) |
| 거절된 화면 | `vault/rejected/<날짜>-<slug>.png` + 같은 이름 `.md`에 거절 이유 한 줄과 관련 규칙 링크 |

토큰을 바꿨다면 `vault/components.html`을 `scripts/shot.sh`로 다시 찍어 직접 확인한다.

## 3. 정리
- 서로 모순되는 규칙, 한 번도 다시 쓰이지 않은 오래된 교정은 삭제를 **제안**한다(바로 지우지 않음).
- Design.md §9 변경 이력에 한 줄 추가.

## 4. 보고
사용자에게 diff 요약: 추가된 규칙 / 승격된 규칙 / 삭제 제안 / vault에 들어간 것. 승인 없이 규칙을 지우지 않는다.
